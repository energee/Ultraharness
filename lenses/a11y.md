# Accessibility — the markup's semantics carry the interaction

Finding slug: `a11y`.

## Definition

In authored UI markup, the element's semantics — not its styling and not its event
handlers — are what a keyboard and assistive technology can use. A control only a
mouse can reach, an image with no text alternative, a field with no name are all the
same defect: the interaction exists visually and is absent from the markup. This lens
judges greppable structure only. It is not a WCAG conformance audit, and it never
grades anything that needs a rendered page.

## Gate — does this lens apply to this repo?

`scripts/audit-checks.sh` decides this and prints the answer. Read its `gates:` line:

```

gates: a11y not-fired
```

The patterns live in the script, in one place, so they cannot drift from the report the
playbooks already quote as fact — and so the same repo gates the same way on every
machine. The script fires on authored-markup extensions — `.html`, `.jsx`, `.tsx`,
`.vue`, `.svelte`, and common server templates (`.erb`, `.twig`, `.haml`,
`.blade.php`) — over authored code only; generated and vendored output is excluded
upstream.

**Applies** if the line reads `FIRED` *and* you open one cited path and confirm
authored UI markup — not a coverage report, a fixture, or generated output that
slipped the exclusions. That confirmation is the one judgement the script cannot make.
If the line reads `not-fired`, or you cannot confirm a hit, this lens does not apply
and is not copied.

## How to spot it

Each of these is grep-first, read-second. The grep gives you candidates; the finding
comes from the read.

- `<img` with no `alt` attribute at all. An empty `alt=""` is a decision (decorative)
  and is not a finding; a missing attribute is an omission.
- A click handler on a non-interactive element — `<div onClick`, `<span onClick` —
  with no `role`, no `tabindex`, and no key handler. Keyboard users cannot reach it.
- A form control with no name: no wrapping or `for`-associated `<label>`, no
  `aria-label`/`aria-labelledby` — a placeholder is a hint, not a name.
- An `<a>` with no `href` doing a button's job, and an icon-only button with no
  accessible name.

## How to fix it

Smallest intervention first:

1. **Use the semantic element** — `<button>` for the clickable div, a real `<a href>`
   for navigation. One tag change usually deletes the ARIA that was compensating.
2. **Name the thing** — `alt` text on the image (`alt=""` if decorative), a `<label>`
   on the control, an `aria-label` on the icon-only button.
3. **Only then ARIA** — `role`, `tabindex`, key handlers — and only where a design
   system genuinely prevents the semantic element.

## When NOT to apply

- **Never claim a conformance level.** "WCAG AA" is a property of a rendered,
  tested page; the finding names the markup defect, nothing more.
- **Color, contrast, focus order, motion** — all need a rendered page and a
  measurement. Out of scope for a code read, however tempting the CSS looks.
- **A design-system wrapper that supplies semantics internally** — read the wrapper
  before flagging its call sites; `<Button>` may already render `<button>` with a
  name. Flag the wrapper if the defect is in it, not the hundred call sites.
- **Generated or third-party markup** — flag the template that generates it only
  where the defect is in the template's own authored lines.
- An empty `alt=""` on a decorative image is correct, not a missing alt.

## Overlap discipline

Near-identical components differing in a literal are DRY; a component with several
reasons to change is SOLID; token duplication is atomic. This lens earns its slot only
for what those cannot name: semantics missing from the markup itself.

## Evidence discipline

Grep results are CANDIDATES, exactly as in DRY. No finding without reading the markup
and naming who is shut out: "the delete control at `Row.tsx:31` is a `<div onClick>`
with no role or tabindex — keyboard users cannot delete" is a finding; "this file has
divs with handlers" is not.
